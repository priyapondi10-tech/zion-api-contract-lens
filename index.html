03 / Change the interface deliberately

API Contract Lens

Review the structural difference between an existing API and its proposed replacement. Spot removed operations, tighter request contracts, weakened response guarantees and authentication changes before consumers are surprised.

Local-only OpenAPI 3.0 / 3.1 JSON comparison. No uploads or API calls. Local JSON-pointer references are resolved; external references are never fetched. This is a focused risk review, not a full OpenAPI validator or compatibility proof.

Coverage and interpretation

Checks operations, inherited/operation parameters, required request bodies, media types, response status removal, local schema references, properties, required guarantees, type sets, enums, array items and selected constraints. Request narrowing and response widening are assessed in opposite directions. Potentially ambiguous removals and security changes are marked for review.

Composition, polymorphism, complex JSON Schema logic, discriminator semantics, server behavior, content negotiation and generated-client behavior are not proven. Changed composition and unresolved references create warnings. Description/example-only edits are ignored. “Likely compatible” is limited to the supported check; it does not certify a release. Run consumer tests and review authentication, idempotency and error behavior manually.
